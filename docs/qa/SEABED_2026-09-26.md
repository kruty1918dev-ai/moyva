# Continuous sloping seabed — implementation report (2026-09-26)

Task: "Суцільне дно водойм із заглибленням від берега" — replace the
repeated per-cell underwater plates with one continuous low-poly bed
that is shallow at the shore and physically deepens toward the middle
of each water body.

## Root cause of the tiled look

Each water cell rendered its own vertical "bed column"
(`TwcTileMeshSourceProvider.CollectWaterBedSource`): the sand theme's
fill tile stretched from the hydrology bed height down past the lowest
neighbour. Per-cell columns produce visible seams, isolated plates and
wavy strips under the water sheet — exactly the reported pattern.

## Implementation

- `RecipeSeabedConfig` (`TerrainPlanConfig.cs`) — JSON-authored profile
  under `hydrology.seabed`: shelf width, falloff, depth exponent,
  per-kind max depths (sea 2 m / lake 1.2 m / river 0.5 m), river
  falloff scale, shore recess, border skirt.
- Config flows through `RecipeHydrologyPlan` → `RecipeHydrologyStore`
  → `IRecipeHydrologyMap.Seabed`; `MergeInto` propagates it.
- `SeabedFieldPlanner` (pure C#): multi-source Dijkstra over water
  cells gives world-space distance to the nearest land-touching cell —
  cannot jump across land into another body. Bed =
  `localWaterSurface − depth(kind, dist)`. A shared `(w+1)×(h+1)`
  corner lattice gives every chunk identical boundary heights; shore
  vertices anchor to `min(land surface, waterline − recess)` so the
  bed meets real banks. Border cells get vertical skirts so map edges
  never open to void.
- `SeabedChunkMeshService` (Zenject, bound in
  `ChunkFirstFeatureBindings`): caches the field per world, emits ONE
  triangle-fan mesh per chunk reusing the sand theme's fill material.
  The mesh is added as a `TileMeshSource` and merged into the existing
  per-chunk combined mesh — no new GameObjects, no new materials.
- `ChunkTerrainMeshBuilder.Build` calls `Prepare` before the canonical
  source plan so `TwcTileMeshSourceProvider` can drop per-cell bed
  columns **only when** the shared field exists (`IsActive && HasField`
  — fallback preserved when the seabed is disabled or unbuildable).
- Water mask = the same criterion the columns used:
  `MainTerrain.TileGeometryMode == SurfaceOnly && Height < SurfaceHeight`
  — cells whose rendered surface is a water sheet with a real
  submerged volume. Flush `water` tiles resting on terrain keep
  contributing their surface as shore heights.

## Ordering bug found and fixed

The first smoke run showed `seabedActive=True` yet `beddedCells=0` and
identical verts: `IsActive` originally required
`IGeneratorTerrainLevelService.HasSurfaceHeightMap`, which on the
chunk-first path is only published **after** `Build`
(`PublishChunkFirstSurfaceHeights`). The field now sources rendered
surface heights from the `resolvedCells` passed into `Build` — always
present at chunk-build time; the level-service dependency is gone.

## Known limitations

- `water`-id flush tiles (95) intentionally carry no bed — they render
  a sheet directly on terrain as before.
- The bed can produce a steep fin at legitimate multi-metre water
  walls (raised river meeting sea); it hides behind the waterfall
  strip but is visible in the isolated render.
- Smoke lighting is dark (documented caveat); material reuse keeps
  the bed consistent with sand shores.
