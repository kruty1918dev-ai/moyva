## New harness — gameplay probe (`RunGameplayProbe`)

The visual smoke previously covered world generation only — the flagged
gap was interactive construction/units/recruitment. This cycle added a
gameplay probe to `Assets/Moyva/Editor/WorldVisualSmoke.cs` that runs
inside the live play-mode session between world capture and the game
shots. It resolves the **canonical** gameplay services through the
Zenject containers (no parallel authority path) and drives them:

- `ConstructionService` — `TryApplySetupPlacement`, `TryDirectPlace`,
  `GetActiveOwner`, `GetLastActionMessage`.
- `UnitRecruitmentService` — `GetOptions`, `TryEnqueue`, `GetQueue`,
  `GetDeploymentTiles`, `TryDeployReady`.
- `ConstructionLifecycleService` — `TryRestoreOperational` (canonical
  save-restore fast-forward).
- `IUnitFactory` — `CreateUnit`.

Reflection is used because the editor assembly cannot name the internal
service types directly (mirrors the existing `FindGeneratorType`
pattern, extended cross-assembly via `TypeCache`).
