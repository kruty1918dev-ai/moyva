# Decor material inspector fix — 2026-09-26

Branch `improvement/moyva-production-polish`. Task `07_Decor_Shader_Inspector.md`.

## Proven cause

`DecorSharedStylized.shader` declares
`CustomEditor "Kruty1918.Moyva.Visuals.Editor.DecorSharedStylizedShaderGUI"`,
but the class no longer compiled anywhere:

- `DecorSharedStylizedShaderGUI.cs` (445 lines, in
  `Features/Visuals/Editor/`) was deleted in `6e7993700` during a bulk
  legacy-editor cleanup.
- Before deletion it was wrapped in `#if MOYVA_LEGACY_SCRIPTABLEOBJECT_EDITOR`
  — a retired define — so the shader's reference had been a phantom even
  while the file existed.
- `Kruty1918.Moyva.Visuals.Editor.asmdef` was deleted in `09041d8c2`
  (the folder was empty by then).

Result: Unity could not create a custom UI for `Moyva/3D/Decor Shared
Stylized` — the warning under 035236. Not a water-artifact cause.

## Why restore rather than delete `CustomEditor`

The GUI is not cosmetic: `OnGUI` calls `EnsureRenderState`, which pins the
shader's hidden pipeline state on every repaint —
`_SrcBlend=SrcAlpha`, `_DstBlend=OneMinusSrcAlpha`, `_ZWrite=1`,
`renderQueue=AlphaTest+40` — plus preset bars that write coordinated
property sets (Card/Mesh/Billboard). The default inspector would let
materials drift from the `TransparentCutout` contract the
`DecorSharedStylizedRendererFeature` depends on. Restoration is the
minimal fix that keeps that validation.

## Changes

- Restored `Assets/Moyva/Scripts/Features/Visuals/Editor/
  DecorSharedStylizedShaderGUI.cs` from `6e7993700~1` **without** the
  retired `#if` guard; original `.meta` guid `bff5b8c2…` preserved.
- Restored `Kruty1918.Moyva.Visuals.Editor.asmdef` +
  `.meta` (guid `1116911a…`) from `09041d8c2~1` — `includePlatforms:
  ["Editor"]`, matching the `Kruty1918.Moyva.<Feature>.Editor` convention.
  UnityEditor dependencies stay out of the runtime `Kruty1918.Moyva.Visuals`
  assembly.
- Shader, materials, `.meta` files: **untouched**.

## Verified

Headless run (`-executeMethod`, probe deleted after use):

- `Kruty1918.Moyva.Visuals.Editor.dll` compiled with zero errors/warnings.
- `TypeCache.GetTypesDerivedFrom<ShaderGUI>()` resolves
  `Kruty1918.Moyva.Visuals.Editor.DecorSharedStylizedShaderGUI` — the exact
  full-name match Unity's `CustomEditor` binding uses → warning eliminated.
- `Grass_kreuz_Mat`, `VegBush_A`, `VegGrass_A`: open, queue 2490,
  `_SrcBlend/_DstBlend = 5/10`, `_ZWrite = 1`; `_ALPHATEST_ON` on the grass
  material. Property edit → `Undo.RecordObject` → `PerformUndo` restores
  0.350 exactly; `SaveAssetIfDirty` + reload returns consistent values;
  multi-select edit across all three materials applies and undoes cleanly.
- No `Could not create a custom UI` or CS errors in the editor log.

## Limits

- Batch mode cannot draw a real inspector window, so lazy instantiation
  inside `OnInspectorGUI` was not observable headless; resolution is proven
  via the same TypeCache mechanism Unity uses for binding, plus clean
  compile and error-free log.
- Vegetation rendering is unchanged by construction — the fix touches only
  editor-side inspector code; no shader/material/serialized data changed.
